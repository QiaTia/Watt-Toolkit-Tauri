## 四、本次审计发现并修复的偏差（2 处）

### 4.1 DNS 污染判定用错解析器（真实影响）
- **原版**：`HttpReverseProxyMiddleware.cs:100-111` 固定用 **DNSPod 公共 DNS** 反查（`AnalysisDomainIpAsync(host, DNS_Dnspods)`），刻意绕过本机 hosts
- **Rust 原状**：`http_relay.rs` 用 `resolve_first()`——**读 hosts 的解析器**
- **后果**：任何存在于本机 hosts 的域名（用户自建条目、上次加速残留、其他软件写入）若不命中加速规则 → 被解析为回环 → 误报「DNS 已被污染」返回 500
- **修复**：新增 `DnsResolver::resolve_first_clean`（`resolver.rs`），污染判定改用它

### 4.2 HTTP→HTTPS 跳转状态码错误
- **原版**：`context.Response.Redirect(...)` 默认 **302 Found**
- **Rust 原状**：`StatusCode::MOVED_PERMANENTLY`（**301**）
- **后果**：301 被浏览器永久缓存，用户关闭加速（或该域名不再需要跳转）后仍被强制 https，恶化体验
- **修复**：改为 `StatusCode::FOUND`（302），测试断言同步更新

验证：全仓 112 测试全绿，clippy 0 error。

|---|---|---|---|

| 3 | **WebSocket/Upgrade 在 MITM 下失效** | 站点功能（实时类） | 出站仅 http1 且 upgrade 属逐跳头被剥离（`http_relay.rs:805`）；纯隧道/CONNECT 模式不受影响 |

| 9 | **无出站连接池** | 高并发握手开销 | 每请求新建 TCP+TLS（原版有 `LifetimeHttpHandler` 生命周期复用 10s/100s） |
| 10 | **`is_proxy_gog` 未接线** | GOG 加速开关无效 | 字段存在但引擎层未消费 |

## 六、建议后续动作

1. **接回脚本子系统**（优先级最高）：`EngineStartParams` 增加 `scripts` 字段 → 前端恢复脚本管理 → 引擎传真实脚本列表。这一步能一次性补齐第 1 项差异。
2. **补 ServerSideProxyToken 获取**：对齐原版 `TryRequestServerSideProxyToken()`（经微服务端取 token 后传引擎）。
3. **出站连接复用 + HTTP/2**：引入连接池与 h2 优先级协商，改善大流量与 h2-only 站点。
4. **WebSocket 透传**：MITM 分支识别 `Upgrade: websocket` 后走双向流复制模式。
5. 若需跨平台系统代理，补 macOS（`networksetup`）/Linux（`gsettings`）实现。

> 注：第 1、2 项是**当前与原版差距最明显的两点**，若原版使用者的加速项中依赖脚本或服务端加速，迁移后会感知到功能缺失；其余差异均不影响常规 Hosts 模式加速。
